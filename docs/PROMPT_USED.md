# Исходный промпт

Ниже — полный текст задания, по которому создана первая версия DocFlow Studio.

---

Ты — senior Python developer, software architect
и опытный UI/UX designer.

Разработай DocFlow Studio — современное desktop-приложение
для автоматической генерации PDF-документов.

Это не учебная демонстрация, а первая версия
потенциального коммерческого продукта.

Главная задача — создать красивое, удобное
и реально работающее приложение для macOS.

Среда разработки: Visual Studio Code.
Платформа: macOS, Apple Silicon.

ТЕХНОЛОГИИ

Python 3
PySide6 — графический интерфейс
WeasyPrint — генерация PDF
SQLite — история операций
CSV / JSON — источники данных
HTML / CSS — шаблоны документов
pytest — тестирование

Никаких серверов, Telegram-ботов, SaaS и облачных сервисов.

Все операции выполняются локально.


========================================
1. ДИЗАЙН — ОСОБЫЙ ПРИОРИТЕТ
========================================

Создай визуально качественное desktop-приложение.

Ориентиры по уровню эстетики:
- Linear;
- Raycast;
- Notion;
- современные приложения macOS.

Не копируй конкретный продукт.
Используй их как ориентиры по качеству UX.

СТИЛЬ

Современный минимализм.

Светлая тема:
- основной фон #F7F8FA;
- карточки #FFFFFF;
- основной текст #171923;
- вторичный текст #717784;
- акцент #5B5FEF.

Тёмная тема:
- основной фон #111318;
- карточки #1B1E26;
- основной текст #F5F6F8;
- вторичный текст #A0A5B2;
- акцент #8588FF.

Используй системные шрифты macOS.

Предусмотри:
- единые отступы;
- скруглённые элементы;
- аккуратные границы;
- визуальную иерархию;
- понятные состояния кнопок;
- иконки в едином стиле;
- плавное обновление данных без мерцания.

Не используй эмодзи вместо иконок.
Не перегружай интерфейс тенями и градиентами.

Сделай интерфейс красивым именно за счёт
композиции, типографики и удобства.

Все надписи должны быть на русском языке.

Окно должно хорошо выглядеть на MacBook Air.

Приоритетное разрешение:
1280×800 и выше.

Интерфейс должен корректно адаптироваться
при изменении размера окна.


========================================
2. ГЛАВНЫЙ ЭКРАН
========================================

Создай интерфейс с тремя рабочими областями.

ЛЕВАЯ ПАНЕЛЬ

Название DocFlow Studio.

Разделы:
- Документы;
- Шаблоны;
- Источники данных;
- История;
- Настройки.

Список шаблонов с небольшими иконками.

ЦЕНТРАЛЬНАЯ ОБЛАСТЬ

Выбор CSV или JSON.

Таблица загруженных данных.

Поиск по записям.

Возможность выбрать:
- одну запись;
- несколько записей;
- все записи.

Отображение количества выбранных документов.

ПРАВАЯ ОБЛАСТЬ

Предварительный просмотр выбранного документа.

Показывай реальный PDF, а не условную картинку.

Поддержи масштабирование предпросмотра.

В нижней части размести заметную кнопку:

«Создать PDF»

После генерации:
- показать сообщение об успехе;
- предложить открыть документ;
- предложить открыть папку результатов.

Предусмотри приятные пустые состояния:
когда шаблон не выбран,
когда данные ещё не загружены,
когда записей нет.


========================================
3. ОСНОВНЫЕ ФУНКЦИИ
========================================

Программа должна:

1. Находить HTML-шаблоны в папках проекта.
2. Находить CSV и JSON во вложенных директориях.
3. Позволять добавлять внешние папки.
4. Показывать доступные файлы.
5. Загружать данные в таблицу.
6. Проверять соответствие полей шаблона данным.
7. Позволять сопоставлять разные названия полей.
8. Показывать предварительный результат.
9. Генерировать PDF.
10. Генерировать несколько PDF за один запуск.
11. Автоматически открывать готовый PDF.
12. Сохранять историю операций.
13. Запоминать недавно открытые файлы.

Не сканируй весь компьютер без разрешения.

Не делай произвольных сетевых запросов.

Данные пользователя должны оставаться локально.


========================================
4. HTML-ШАБЛОНЫ
========================================

Создай три красивых демонстрационных шаблона.

ШАБЛОН 1 — ТОВАРНЫЙ ЧЕК

Аккуратный современный документ.

Содержит:
- название продавца;
- номер документа;
- дату;
- название товара;
- количество;
- цену;
- итоговую сумму.

Используй плейсхолдеры:

{{ id }}
{{ product }}
{{ price }}
{{ qty }}
{{ total }}

Добавь пометку:
«Демонстрационный нефискальный документ».

ШАБЛОН 2 — СЧЁТ НА ОПЛАТУ

Профессионально оформленный документ A4.

С вымышленными реквизитами.

Таблица товаров, стоимость, итог.

ШАБЛОН 3 — СЕРТИФИКАТ

Красивый документ A4.

Имя получателя, название программы,
дата выдачи и номер сертификата.

Для всех шаблонов:

- качественная типографика;
- поддержка кириллицы;
- правильные поля страницы;
- перенос длинного текста;
- аккуратные таблицы;
- согласованное оформление.

Это должны быть красивые готовые PDF,
которые можно использовать в демонстрации продукта.


========================================
5. ДАННЫЕ
========================================

Создай демонстрационные CSV и JSON.

В каждом наборе минимум 5 записей.

Используй только вымышленные данные.

Для товарных чеков:

id,product,price,qty

Примеры:
- ноутбук;
- смартфон;
- монитор;
- клавиатура;
- наушники.

Должны корректно работать:
- кириллица;
- UTF-8;
- UTF-8 BOM;
- Windows-1251;
- разделители CSV;
- длинные названия товаров.

Для денежных расчётов используй Decimal.


========================================
6. ГЕНЕРАЦИЯ PDF
========================================

Используй WeasyPrint.

Поддержи:
- A4;
- формат кассовой ленты;
- кириллицу;
- многостраничные документы;
- таблицы;
- длинные строки;
- массовую генерацию.

PDF сохраняй в папку:

output/

Не перезаписывай существующие документы.

Формируй уникальные имена.

При генерации одного PDF
автоматически открывай его через macOS.

При генерации нескольких документов
предлагай открыть папку результатов.

Не отправляй документы на физический принтер
без отдельного действия пользователя.


========================================
7. CLI — ДОПОЛНИТЕЛЬНЫЙ РЕЖИМ
========================================

Кроме графического интерфейса,
реализуй полноценный CLI.

Запуск GUI:

python3 main.py

Запуск CLI:

python3 main.py --cli

В CLI должно быть меню:

1. Выбрать шаблон
2. Выбрать данные
3. Выбрать запись
4. Создать PDF
5. Создать PDF для всех записей
6. Открыть результат
7. Выход

CLI и GUI должны использовать
одно ядро генерации документов.

Не дублируй бизнес-логику.


========================================
8. АРХИТЕКТУРА
========================================

Раздели проект на:

- UI;
- загрузку CSV/JSON;
- поиск файлов;
- работу с шаблонами;
- генерацию PDF;
- настройки;
- историю операций;
- CLI.

Не создавай микросервисы.

Не усложняй архитектуру без необходимости.

Реализуй чистое независимое ядро,
чтобы в будущем можно было подключить:

- Telegram;
- REST API;
- CRM;
- 1С;
- облачную версию.

Но сейчас НЕ реализовывай эти интеграции.

Это только архитектурная возможность.


========================================
9. КАЧЕСТВО И БЕЗОПАСНОСТЬ
========================================

Добавь обработку ошибок.

Не допускай аварийного завершения при
пустых или некорректных файлах.

Проверяй обязательные поля.

Экранируй данные при подстановке в HTML.

Не позволяй шаблонам выполнять произвольный код.

Запрети сетевые загрузки ресурсов при рендеринге.

Не добавляй пользовательские данные в логи.

Длительные операции выполняй без блокировки GUI.

Показывай пользователю понятные сообщения
об ошибках на русском языке.


========================================
10. ПРОВЕРКА ВНЕШНЕГО ВИДА
========================================

Особое внимание удели UI.

Не ограничивайся тем, что окно просто открывается.

Проверь:
- расположение элементов;
- размеры кнопок;
- читаемость текста;
- отступы;
- поведение при изменении размеров окна;
- тёмную и светлую темы;
- состояния без загруженных файлов;
- внешний вид таблиц;
- качество предпросмотра PDF.

Если доступны средства для визуальной проверки,
сделай скриншоты интерфейса.

Если визуально проверить GUI невозможно,
не утверждай, что дизайн проверен.
Попроси пользователя открыть приложение
и предоставить скриншот.

Исправь выявленные проблемы компоновки.

Избегай типичного вида учебного приложения:
маленькое окно, стандартные серые кнопки,
тесные поля, хаотичная компоновка.

========================================
13. КРИТЕРИИ ГОТОВНОСТИ
========================================

Продукт считается готовым, если:

1. Приложение запускается на macOS.
2. Интерфейс выглядит современно и аккуратно.
3. Пользователь выбирает HTML-шаблон.
4. Пользователь загружает CSV с пятью записями.
5. Пользователь выбирает конкретную запись.
6. Видит корректный предварительный PDF.
7. Создаёт документ одной кнопкой.
8. PDF сохраняется в output.
9. Готовый PDF автоматически открывается.
10. CLI также выполняет генерацию документов.
11. Автоматические тесты проходят.
12. Проект готов к размещению на GitHub.

Сначала реализуй работающий генератор и CLI,
затем графический интерфейс и его оформление.

Не жертвуй работоспособностью ради дизайна,
но не считай задачу завершённой только потому,
что функции технически работают.

В конце предоставь:
- краткий отчёт;
- результаты тестов;
- инструкцию запуска;
- перечень ограничений;
- список файлов для GitHub.
