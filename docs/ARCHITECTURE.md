# Архитектура DocFlow Studio

DocFlow Studio — локальное настольное приложение. Здесь нет серверов, микросервисов
и сетевых вызовов. Вся бизнес-логика собрана в независимом ядре `docflow/core`,
которым одинаково пользуются графический интерфейс и консоль.

```
main.py                 точка входа: GUI по умолчанию, --cli — консоль
docflow/
├── core/               ядро без Qt и без ввода-вывода в консоль
│   ├── engine.py       DocFlowEngine — единый фасад для всех клиентов
│   ├── data_loader.py  чтение CSV/JSON, кодировки, разделители, выбор и поиск записей
│   ├── discovery.py    поиск шаблонов и данных только в разрешённых папках
│   ├── templates.py    метаданные шаблонов, обязательные поля, сопоставление колонок
│   ├── template_engine.py  безопасный шаблонизатор {{ поле }}, for, if, фильтры
│   ├── calculations.py вычисляемые поля: стоимость позиций, итого, НДС, к оплате (Decimal)
│   ├── money.py        разбор и форматирование сумм по-русски
│   ├── renderer.py     WeasyPrint с запретом сетевых ресурсов
│   ├── naming.py       уникальные имена файлов без перезаписи
│   ├── history.py      история операций в SQLite
│   ├── settings.py     настройки, недавние файлы, папки, сопоставления
│   ├── system.py       открыть файл или папку средствами macOS
│   ├── models.py       структуры данных (Record, DataSet, TemplateInfo, BatchResult…)
│   └── errors.py       исключения с понятными русскими сообщениями
├── cli.py              интерактивное меню и запуск с аргументами
└── ui/                 PySide6
    ├── app.py          создание QApplication, стиль, шрифт
    ├── main_window.py  окно-контроллер: состояние, фоновые задачи, связи
    ├── documents.py    экран «Документы»: таблица, поиск, выбор, панель предпросмотра
    ├── pages.py        Шаблоны, Источники данных, История, Настройки
    ├── dialogs.py      сопоставление полей
    ├── widgets.py      карточки, пустые состояния, плашки, сегменты
    ├── theme.py        палитры и таблица стилей светлой и тёмной тем
    ├── icons.py        SVG-иконки в едином стиле, перекраска под тему
    └── workers.py      QRunnable-задачи для работы без блокировки интерфейса
templates/              HTML-шаблоны (чек, счёт, сертификат)
data/                   демонстрационные CSV и JSON
output/                 готовые PDF (в Git не попадают)
tests/                  pytest
```

## Поток данных

```
CSV / JSON ──► data_loader ──► DataSet (Record[])
                                  │
HTML-шаблон ──► templates ──► TemplateInfo + CompiledTemplate
                                  │
              validate / сопоставление полей (settings хранит выбор)
                                  │
Record ──► apply_mapping ──► calculations.enrich (Decimal) ──► проверка обязательных полей
                                  │
                       template_engine.render (экранирование)
                                  │
                renderer.render_pdf (WeasyPrint, только локальные ресурсы)
                                  │
            naming.reserve_path (атомарно, без перезаписи) ──► output/*.pdf
                                  │
                         history.add (SQLite)
```

## Ключевые решения

**Одно ядро.** `DocFlowEngine` — единственное место, где выполняются загрузка,
проверка, расчёты и генерация. CLI и GUI только собирают ввод пользователя и
показывают результат. Будущие клиенты (Telegram, REST API, CRM, 1С, облачная
версия) смогут подключиться к тем же методам: `list_templates`, `load_data`,
`validate`, `render_html`, `render_to`, `generate`. Сейчас эти интеграции
сознательно не реализованы.

**Собственный минимальный шаблонизатор вместо Jinja2.** Шаблон может только
подставлять значения из словаря, проходить по списку и проверять условие.
Вызовов функций, арифметики и доступа к атрибутам Python нет вообще — это
проще проверить, чем песочницу полноценного движка. Все значения проходят через
`html.escape`. Набор фильтров фиксирован: `money`, `number`, `date`,
`date_long`, `default`, `upper`, `lower`, `capitalize`, `count`.

**Метаданные шаблона — в HTML-комментарии.** Блок `<!-- docflow ... -->`
задаёт название, описание, иконку, формат страницы и (необязательно) список
обязательных полей. Если `required` не указан, обязательными считаются все
поля, использованные вне `{% if %}` и без фильтра `default`, кроме вычисляемых.

**Проверка данных до рендеринга.** Ядро знает, какой тип ждёт каждое поле: по
фильтрам шаблона (`date`, `date_long` — дата; `money`, `number`, `in_words` —
число) и по циклам (`{% for %}` — список). Неверное сопоставление (текст в дате,
строка вместо позиций) превращается в понятную ошибку, а не в мусор в PDF.
Пустые значения выводятся пустой строкой — слово «None» в документ не попадает.
`compatible_files()` подбирает файлы данных, в которых есть все поля шаблона.

**НДС по российским правилам.** По умолчанию цены включают налог
(«В том числе НДС»), `vat_included: false` — начисление сверху. Сумма прописью
склоняется по родам и числам (одна тысяча, два миллиона, один рубль 01 копейка).

**Decimal во всех расчётах.** Суммы разбираются из строк вида «1 234,50»,
«1,234.50», «12 990,99 ₽»; float из JSON переводится через строку без потери
точности; округление — `ROUND_HALF_UP` до копеек.

**Безопасный рендеринг.** Свой `URLFetcher` пропускает только `data:` и файлы
внутри папки шаблона. Любой `http(s)`, `ftp` и файлы вне папки шаблона
блокируются; в журнал пишется только схема адреса.

**Не перезаписываем файлы.** Имя: `<шаблон>_<метка-записи>_<дата-время>.pdf`.
Файл создаётся в режиме `xb` (атомарно); при совпадении добавляется `-2`, `-3`…
Если PDF создать не удалось, зарезервированный файл удаляется.

**Отказоустойчивость пакета.** Ошибка одной записи не останавливает пакет:
результат каждой записи возвращается отдельно, интерфейс показывает итог
«Создано N из M» и первую причину ошибки.

**Интерфейс не блокируется.** Загрузка данных идёт в общем пуле потоков.
Предпросмотр и генерация — в отдельном пуле из одного потока (WeasyPrint и
Pango рендерят последовательно). Запросы предпросмотра нумеруются, устаревшие
результаты отбрасываются; новый PDF подменяет старый только после готовности,
поэтому мерцания нет. Генерацию можно отменить.

**Приватность.** Журнал (`logging`) содержит только служебные сведения:
количество записей, формат, тип ошибки. История в SQLite хранит время, шаблон,
имя файла данных, количество документов, статус и пути к PDF — без значений
полей. Настройки и история лежат в
`~/Library/Application Support/DocFlow Studio/` (для тестов — `DOCFLOW_HOME`).

**Поиск файлов ограничен.** Сканируются только `templates/`, `data/` проекта и
папки, которые пользователь добавил сам. Скрытые папки, `.venv`, `output`,
`node_modules` пропускаются; глубина и количество файлов ограничены. Добавить
корень диска или всю домашнюю папку интерфейс не даст.

## Как добавить новую интеграцию в будущем

```python
from pathlib import Path
from docflow.core import DocFlowEngine

engine = DocFlowEngine(Path("/путь/к/проекту"))
info = engine.find_template("invoice")
dataset = engine.load_data(Path("orders.json"), remember=False)
result = engine.generate(info, dataset, dataset.records, source="api")
paths = [doc.path for doc in result.succeeded]
```

Для источника данных не из файла (CRM, 1С) достаточно собрать `DataSet` из
`Record` в памяти — остальная цепочка не меняется.
